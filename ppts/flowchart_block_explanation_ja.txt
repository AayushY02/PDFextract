フローチャート各ブロックの説明（やさしい日本語）
==================================================

この説明は、現在のフローチャート
「プロジェクト処理フロー（同系色デザイン／編集可能）」に対応しています。


1. フォルダ内の新規入力資料を確認
--------------------------------
何をするか:
- 処理対象の新しい資料があるか、入力フォルダを見ます。

システム動作:
- まず処理の開始準備をします。
- 前回処理済みのものと区別しながら、対象候補を探します。


2. input/ から PDF・DOCX・XLS・XLSX を収集
------------------------------------------
何をするか:
- `input/` 配下から、対応形式ファイルを集めます。

システム動作:
- サブフォルダも含めてファイル一覧を作ります。
- 抽出に必要な作業キューを作成します。


3. 判定: 入力対象ファイルがあるか
--------------------------------
Yes のとき:
- 次の抽出ステップへ進みます。

No のとき:
- 「入力待ち」へ進み、今回は終了します。

システム動作:
- ファイル件数を見て、処理継続か停止かを自動で分けます。


4. 入力待ち（終了）
------------------
何をするか:
- 今回処理するファイルがないため、待機状態にします。

システム動作:
- 処理はここで止まります。
- 新しいファイルが置かれたら、次回実行で再開できます。


5. text_extractor.py / hybrid_extraction.py を実行
--------------------------------------------------
何をするか:
- 2系統の抽出を行います。
  - 標準抽出: `text_extractor.py`
  - ハイブリッド抽出: `hybrid_extraction.py`

システム動作:
- `input/` の資料からテキストを取り出します。
- 抽出結果を次のフォルダへ出力します。
  - 標準系: `results/output1`
  - ハイブリッド系: `results/test1`
- 抽出ログも記録します。


6. text_cleaner.py（output1->output2 / test1->test2）
-----------------------------------------------------
何をするか:
- 抽出直後のテキストを読みやすく整えます。

システム動作:
- 不要文字・不要行の整理、正規化などを行います。
- 2系統それぞれを別フォルダへ保存します。
  - `results/output1 -> results/output2`
  - `results/test1 -> results/test2`


7. post_clean_output3.py（output2->output3 / test2->test3）
-----------------------------------------------------------
何をするか:
- クリーニング後のテキストを、さらに後処理して完成形に近づけます。

システム動作:
- 後工程（DSL抽出）で使いやすいように調整します。
- 出力先:
  - `results/output2 -> results/output3`
  - `results/test2 -> results/test3`


8. 判定: 86/89 のマージ対象があるか
-----------------------------------
Yes のとき:
- 86/89 用のマージ処理を実行します。

No のとき:
- マージ処理はスキップして、主系統DSLへ進みます。

システム動作:
- 86/89 で必要な入力がそろっているかを確認します。


9. merge_86_texts.py / merge_89_texts.py
---------------------------------------
何をするか:
- 86 と 89 のテキストを、DSLに渡しやすい形にまとめます。

システム動作:
- `results/test3` の対象テキストを結合・整理します。
- マージ後データを `results/test4` 側へ出します（86/89系）。


10. dsl_engine.py（主系統）
-------------------------
何をするか:
- 地域ごとの DSL スクリプトを実行して、項目を抽出します。

システム動作:
- 主系統入力:
  - `results/output3`（82,83,84,87,88,90）
  - `results/test3`（85,810-819）
- ルールに沿って情報をCSV形式へ変換します。


11. dsl_engine.py（86/89, input:test4）
--------------------------------------
何をするか:
- 86/89 のマージ後データに対して DSL 抽出を行います。

システム動作:
- `results/test4` を入力して 86/89 のCSVを生成します。
- 主系統のCSV結果と同じ出力体系にそろえます。


12. results/csv/<地域>
---------------------
何をするか:
- DSL抽出結果のCSVを地域別に保存します。

システム動作:
- 代表的な出力:
  - `<name>.csv`
  - `*_all_texts_summary.csv`
  - `*_levels_summary.csv`


13. 判定: Excel統合を作成するか
------------------------------
Yes のとき:
- `merge_region_summaries.py` を実行します。

No のとき:
- CSV出力のまま完了へ進みます。

システム動作:
- 統合レポートが必要かどうかを分岐します。


14. merge_region_summaries.py（任意）
-----------------------------------
何をするか:
- 地域別CSVのサマリをExcelにまとめます。

システム動作:
- `results/csv` のサマリCSVを読み込み、
  `merged_*_summary_*.xlsx` を作成します。


15. 処理完了
-----------
何をするか:
- 一連の処理が終了した状態です。

システム動作:
- 実行を終了し、次回の入力待ちになります。


--------------------------------------------------
補足（貼り付け用の短いまとめ）
--------------------------------------------------
- 入力確認 -> 抽出(2系統) -> クリーニング -> 後処理
- 必要なら 86/89 をマージ
- DSLでCSV化（主系統 + 86/89系）
- 必要なら Excel統合
- 完了
